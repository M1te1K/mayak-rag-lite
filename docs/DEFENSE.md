# Как объяснить проект проверяющему

Я выбрал вариант 1: поиск по локальному PDF позволяет показать RAG, проверяемые источники и честный отказ без зависимости от веб-поиска. В задании разрешён CLI и локальная база знаний.

`cli.py` только собирает компоненты и общается с терминалом. `Bot.handle()` понимает команды, определяет режим, хранит историю и превращает ошибки в требуемую фразу. Из-за этого Telegram можно добавить без переписывания поиска и ответов.

PDF читается через pypdf. Сохраняем номера страниц, делим текст по токенам E5 с перекрытием и назначаем ID. E5 small подходит для русского и поиска короткого вопроса по фрагментам. Важно использовать `query:` для вопроса, `passage:` для текста и нормализацию. Тогда скалярное произведение - cosine similarity. Сортируем NumPy-массив, отдельная векторная БД для одного PDF не нужна.

Score показывает близость текста к вопросу, а не наличие ответа. Поэтому LLM выбирает цитаты и возвращает структурированный результат. Python проверяет типы, существование источников и цитаты в тексте. Свободный ответ модели не показываем: он мог бы содержать выдуманную деталь даже рядом с настоящей цитатой. Ещё один вызов оценивает, отвечают ли цитаты на весь вопрос. Если нет, расширяем поиск соседями, затем отказываем. Но если чанк не влезает в бюджет, конфигурация отклоняется до диалога; если выбранные кандидаты частично пропущены из-за совокупного бюджета, выдаётся техническое ограничение, а не утверждение об отсутствии факта.

Это консервативная система с извлечением цитат. Она уменьшает риск добавления фактов, но не гарантирует смысловую правильность выбора: проверяющая модель тоже может ошибаться. Для расчётов и сложных выводов нужна отдельная логика. Проверка реальной модели по контрольным вопросам обязательна до заявления о её качестве.

История ограничена парами вопрос-ответ и символами. Уточнение «а сколько это стоит?» получает предыдущую тему и тот же режим. `/reset` стирает историю, режим и незавершённое уточнение; индекс документа не является диалоговой памятью и остаётся. Логи также остаются, чтобы разобрать работу.

Бесплатность Groq зависит от Free Plan аккаунта; тариф по ключу не определялся и не изменялся. OpenRouter переключается вручную на точный `:free` ID с нулевой допустимой ценой и отключёнными fallback. Embeddings локальные. Встроенные веб-инструменты API не подключены. Ошибки не запускают платные запасные маршруты.

На показе откройте CLI и второй терминал с `tail -f logs/bot.jsonl`. Задайте общий вопрос, факт, перефразирование, вопрос без ответа, провокацию ответа из знаний, уточнение, reset. Покажите найденные/переданные/процитированные фрагменты. Автотесты с подменой доказывают обработку ошибок и программные ограничения; они не доказывают качество живой LLM.

После аудита добавлена программная маршрутизация известных запросов текущего курса и времени. У бота нет таких инструментов, поэтому он сразу сообщает ограничение, не просит модель придумать число. Короткие продолжения сохраняют тему, определения и статические числа идут в LLM. Заглушки отклоняются до записи в историю. Это ограниченный набор правил, а не полная проверка актуальности произвольного текста.

Идентификатор запроса задаётся контекстным менеджером Audit. ContextVar привязывает его к текущему выполнению и сбрасывает после запроса, поэтому вложенные вызовы, ошибки и расширение поиска получают один ID без передачи mutable-поля между запросами. Отдельный тест перемежает два потока с общим журналом и проверяет изоляцию ID и маскирование секретов. Для полноценного многопроцессного сервиса всё равно нужен подходящий сборщик логов: текущая файловая ротация рассчитана на CLI.

Проверки 15 октября разделены: 98 автоматических тестов (LLM подменена), настоящий E5-поиск и живой Groq. Независимый прогон Groq дал 3/3 до исправлений; результаты нового прогона находятся в docs/VALIDATION.md. OpenRouter живыми запросами не проверялся. Нельзя выдавать наличие цитаты, 7/7 поиска или PASS smoke test за гарантию отсутствия всех смысловых ошибок.
